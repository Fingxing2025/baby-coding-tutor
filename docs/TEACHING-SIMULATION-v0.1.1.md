### Final（原文；文件路径如有则脱敏）

理解 Skill → 这一步看它解决什么问题 → 下一步再拆完整文件。

假设你每次让 AI 解释 C++，都希望它：

1. 先说代码接收什么、产生什么。
2. 用一个小例子，按执行顺序走一遍。
3. 遇到陌生词，先用日常语言解释。

每次都重新输入这些要求，很重复。**Skill 就是把一套可以反复使用的做事方法保存下来，让 AI 在相关任务中读取并照着做。** Skill 的英文意思是“技能”。[官方说明](https://learn.chatgpt.com/docs/build-skills)

你熟悉函数：把常用的计算步骤写进函数，以后再调用。Skill 也有“保存方法、重复使用”的作用，但读取它的是 AI：C++ 函数由程序执行，Skill 的文字由 AI 理解并遵循，所以仍要观察实际效果。

比如，你这次说“解释这段 `for` 循环”，告诉我的是**这次要做什么**；上面的三条要求告诉我的是**用什么方法做**。换另一段代码，那套方法仍然能用。

实际保存时，一个 Skill 有自己的文件夹，其中有一个名叫 `SKILL.md` 的入口文件。它放名称、用途和详细做法，也可以带辅助文件。[文件结构说明](https://learn.chatgpt.com/docs/build-skills)

这里的 `.md` 是文件名的后缀，表示里面用 **Markdown** 写文字。Markdown 就是普通文字加少量标记，例如：

```markdown
# 解释代码的方法

先说输入和输出。
再用一个小例子走一遍。
```

`#` 后面留一个空格，表示这一行是标题；下面两句就是普通文字。支持 Markdown 的阅读工具会把标题显示得更醒目。这段是说明内容的示意，还不是一份完整 Skill。

刚才我已经真实读取了 baby-coding-tutor 的说明，其中要求从你已知的内容出发、每轮只推进一个小目标；这就是一次读取 Skill 后使用它的例子。本轮没有创建文件。

这是**相对于当前项目文件夹**的位置：`/` 分开一层层文件夹；`.agents/skills` 是 Codex 查找项目 Skill 的约定位置，`explain-command` 放我们这一个 Skill。`.agents` 开头的点通常让文件夹在文件管理器中隐藏。[位置约定](https://learn.chatgpt.com/docs/build-skills)

`SKILL.md` 是入口文件名。中间的点把名字和后缀分开；`md` 表示 Markdown。你可以把 Markdown 理解为“普通文字，加少量用于排版的标记”。例如 `# 拆开解释陌生命令` 中，`#` 后留一个空格，表示这是标题。这些文字供 AI 阅读，不需要像 C++ 那样编译。

准备写入的完整内容是：

```markdown
---
name: explain-command
description: 当用户想理解一条陌生命令时，拆开解释命令的用途、各部分写法和预期结果。
---

说清执行位置、预期结果和验证方法；用户只要求讲解时，不执行命令。
```

最上面两行 `---` 各有三个短横线，标出**文件头**的开始和结束。文件头就是供 Codex 识别的说明卡；下面才是详细做法。

`description` 意思是“描述”，这一行告诉 Codex什么时候该考虑使用它。文件头的这套写法叫 YAML；这一步只需要这两项，不用先学整套语法。两道 `---` 外面的正文，则告诉 AI 具体怎样解释。

### Commentary / 工具动作

### Final（原文）

我们停在这一行：

```text
name: explain-command
```

把它读成一句话：**“这个 Skill 的名字是 explain-command。”**

- 冒号左边的 `name`：告诉 Codex，“这里填写的是名字”。
- 冒号右边的 `explain-command`：我们填进去的具体名字。
- 中间的 `:`：把“填什么”和“填入的内容”分开，后面留一个空格。

为什么左边不能改成“名字”？因为 Codex 约定寻找的是 `name` 这个固定写法。写成：

```text
名字: explain-command
```

人能看懂，但 Codex 按约定找 `name` 时，就找不到这一项。这个固定名称来自 [Skill 文件格式](https://learn.chatgpt.com/docs/build-skills)。

可以这样记：**左边是固定的栏目名称，右边是我们给这个 Skill 起的名字。**

它的用途是：**询问 Python 3 程序自己的版本号。** 它不会安装 Python，也不会修改项目文件。
