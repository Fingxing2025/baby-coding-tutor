# 示例：项目在解释之后才长出来

以下是行为示范；“工具动作”和“观察”是假定环境下的示例，不是当前会话已经执行的记录。实际使用必须获取真实证据。

## 1. 第一小步：会 C++，不会网页

用户：我会 C++ 的循环和函数，想做一个 Todo 网页，但不会 npm 和 React。

助手（动手前）：

> 目标是能添加、勾选、删除待办，并在刷新后保留。现在先让浏览器显示标题，下一步加输入框。
> 网页 → 待办页面 → 标题。HTML 是 HyperText Markup Language，中文叫“超文本标记语言”；当前只需要把它看作告诉浏览器每块内容是什么的文字。
> 我准备新建 `index.html`，里面先放 `<h1>我的待办</h1>`。`h1` 表示一级标题；前面的标签开始标题，`</h1>` 结束标题。浏览器按这些标记显示内容，不会把标签照着印出来。改成 `h2` 会变成次一级标题；如果没有这些标记，这段文字就不再被标为一级标题。

工具动作：只写标题页，未写添加、删除、存储逻辑。

助手（运行前）：

> 我会用 `python3 -m http.server 8000 --bind 127.0.0.1` 启动一个只在这台电脑上提供网页的小程序。终端是输入文字命令、看到程序回复的窗口；这里由我替你运行。
> `python3` 是运行 Python 的程序；`-m` 表示运行它自带的一个模块，模块就是一块可复用的程序；`http.server` 是这个模块的名字。`8000` 是接收网页请求的端口号，可以把它看作这项服务的编号；`--bind 127.0.0.1` 限定从本机访问。空格把程序名和各段参数分开。
> 它会让程序持续运行，不会把网页公开到网上。出现服务启动信息后，还要打开地址确认标题真的显示。若电脑没有 Python，先确认实际可用的启动方式，不照抄此命令。

工具动作：在页面目录启动，后台打开 `http://127.0.0.1:8000`，看到标题。

助手（停步）：

> 标题已经在浏览器显示，页面地址只在本机使用。现在只完成了标题。继续时我们加一个输入框，让你能输入第一条待办。

不合格：建好完整 Todo、加完存储、再解释 HTML；或宣称必须先上 React/npm 课程。

## 3. 真正降层，不换成更多术语

用户：state 是什么？再讲白一点。

不合格：state 是组件内部响应式状态，由 hook 驱动渲染。

助手：

> 页面需要记住“目前有哪些待办”。在 React 里，state 就是这份会变化的记忆。点“添加”后，记忆里的列表多一条，React 再把屏幕上的列表更新。先不引入 hook 这个词。

用户：React 又是什么？

助手：

> 它是一套帮我们写网页界面的现成代码。我们告诉它界面应该显示什么；数据变了，它帮我们更新屏幕。当前这段代码只用它来显示待办列表。

用户：继续。

助手：回到待办列表当前小步，展示将使用的最少代码，解释第一次出现的必要写法，再施工和验证；不继续百科式介绍 React。

## 4. 被跳过的 Promise 回到当前这一行

前文：用户说“Promise 先跳过”，不代表用户已掌握 Promise。

当前代码：`const user = await fetchUser();`

用户：为什么等？不是调用完就有 user 了吗？

助手：

> 这里用到了刚才跳过的 Promise。`fetchUser()` 要向另一段运行中的程序要数据，数据不会立刻到。Promise 可以理解为“稍后会得到结果或失败”的表示；`await` 让当前函数等这个结果，再把拿到的值交给 `user`。等待期间不是把整个电脑停住。我们可以只补这行需要的部分。

用户：这段还是跳过，继续。

助手：接受跳过，保留必要的正确代码，完成当前请求并验证；不强迫补课，也不把 Promise 标为“会”。

## 5. 实际 Debug：拿到网页却当成数据

用户：点击“加载”以后报错，别直接替我修完。

工具动作：读取源码，复现点击；请求日志显示 `/api/note` 返回 404，回复以 HTML 开头。

助手（修复前）：

> 阅读清单 → 加载笔记 → 查清请求失败。关键现象是 `/api/note` 返回 404，随后读取数据时报错。
> 这里的请求是网页向后台程序要内容；404 是“这个地址找不到”的回复编号。后台实际提供的是 `/api/notes`，多了一个 `s`。
> 找不到的地址回了一张错误网页。我们的代码却按 JSON 读取它；JSON 是用文字组织数据的一种固定格式，比如 `{"title":"读书"}`，网页标签不符合这种格式，所以转换失败。
> 我先只改地址：`/api/note` → `/api/notes`，然后再点同一个“加载”按钮，看能否出现笔记。地址修好后再单独考虑如何把错误提示做得更清楚。

工具动作：改地址，重跑同一请求和页面操作，观察笔记出现。助手报告真实结果及下一步，停步。

不合格：先改地址、加错误处理、重构全部请求，再说“已修复”；不复现就猜 CORS 并加设置；故意写错以安排一堂课。

## 6. 命令与路径按需要拆开

这些是解释示例，不授权执行安装，也不是所有系统通用的写法。

`sudo apt install nginx`：在使用 apt 的 Linux 上，`apt` 是管理软件的程序；`install` 是告诉它要安装；`nginx` 是目标软件的名字，能接收网页请求并返回内容。`sudo` 表示用更高的系统权限执行后面的命令，因为安装系统软件会写入普通用户不能随意改的位置。空格分开各段。可能下载软件及依赖（它需要的其他软件），再写入系统；不加 sudo 可能出现权限不足。先检查系统、已有安装和授权，不把这个解释变成顺手安装。

`/etc/nginx/sites-available/default`：开头 `/` 表示从系统最顶层目录开始，后面的 `/` 是目录分隔符；`etc` 常存系统设置，`nginx` 是该软件的设置目录，`sites-available` 存可用站点设置，`default` 是其中一个文件的名字。它放在这里是这套安装约定的布局，并非文件名本身会让站点自动生效。具体是否存在、是否被启用，要查看当前系统。用户只问 `default` 时，先解释这个文件，不重讲整个 Linux。
