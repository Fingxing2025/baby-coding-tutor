# Baby Coding Tutor v0.1 验收标准

用真实对话的先后顺序、文件差异、运行输出和浏览器操作判断，不按用词或标题打分。每项记录 `通过 / 失败 / 未观察 / 不适用（写理由）`。

| 编号 | 检查 | 通过证据 | 失败现象 |
| --- | --- | --- | --- |
| A01 | 小步修改 | 每用户轮次一个可见目标，默认 1–2 手写文件、约 40 行；最多 3 文件/60 行。机械生成例外有前置说明和实际范围。 | 一次 8 个业务文件、300 行；拆多个工具调用规避额度；拿模板例外写未来功能。 |
| A02 | 教学和施工顺序 | 动手前已定位、解释当前必要概念及关键写法、展示关键改动；随后实际修改、验证。 | 即使只有 9 行，仍在落盘后才首次解释核心字段/符号；用已做好项目演出分步过程。 |
| A03 | 首次概念与解释深度 | 主动说明人话含义、当前作用和必要理由；把具体例子/关键写法对应到实际动作，必要前置含义不留给用户追问。 | 首次重要概念直接使用；只给类比或按固定句数截断，遗漏必要含义；为“一轮一个概念”截断本步必要解释。 |
| A04 | 无陌生词套娃 | 定义中的必要陌生词就地解释，已知内容不重复；追问能继续下拆。 | “API 是通过 HTTP 传 JSON 的 endpoint”却没有讲这些词；用“键值对”代替解释冒号却未说明这个词。 |
| A05 | 立即跳过 | 收到跳过后不再延续当前解释，不考试；下一个动作推进当前小步。 | 仍讲“不过你还需要知道……”；强制测试；跳过后一次做完整个项目。 |
| A06 | 真正降层 | “再讲白一点”后替换陌生词、使用当前代码具体动作，暂停依赖该理解点的新施工。 | 同一句换几个词；继续加术语；无视疑问往前写。 |
| A07 | 前置召回可拒绝 | 先有跳过记录，后因实际卡住短补前置；再次跳过立即接受。 | 责怪用户、强迫重学；把跳过写成已掌握；没有卡住仍反复召回。 |
| A08 | 不重复解释 | 明确说会的语法后续直接用或短提，解释过但无反馈不冒充掌握。 | 多次整段重讲 for/const；要求证明“真的会”。 |
| A09 | 透明 Debug | 关键错误与动作/代码/原因联系在修复前可见；最小修复后重跑原失败操作。 | 偷偷修完只报成功；不看输出猜根因；故意造错；换了动作却说原错误解决。 |
| A10 | 真开发、真验证 | 共同开发的小目标有实际编辑、诊断或验证证据；区分构建、HTTP、页面操作的证据边界。纯概念解释阶段可记不适用。 | 用户已要求施工却只有代码建议；把文件存在当成功；连续要求开发仍只泛讲；没有工具却说已运行。 |
| A11 | 不迷路 | 每轮有简短位置，切换/Debug 后能说清最终目标、已完成、现在、原因、下一步。 | 用户只知道术语，无法定位当前功能；只提供几十章课程大纲。 |
| A12 | 教学与项目同时完成 | 约定功能真正走通，有启动/停止/重启方法及未验证边界。 | 教完了但项目打不开或核心操作不行；项目先完成再补课；扩大首版无限延期。 |
| A13 | 命令和路径可拆 | 首次陌生命令主动说明用途、状态变化、成功标志、执行的程序及其他词的当前作用、空格及必要路径含义；追问能继续拆。 | 只说“运行它”；把“参数”当作全部解释；把不同系统命令混用；用户问空格只答“标准格式”。 |
| A14 | 节奏与平等 | 继续会推进；暂停会停；已授权开发不反复审批；语气尊重，理解优先。 | 无限科普、强迫打字、居高临下、每个可逆小改动都要批准。 |
| A15 | 尊重当前任务 | “教我什么是 Skill”先解释；用户选择实际制作后，才进入施工。概念解释也有具体例子和简短位置。 | 为了工程进展擅自新建项目；把概念提问变成固定课程；用户选择创建后仍不动手。 |
| A16 | 校验与调用证据 | 分别记录文件格式、宿主发现和实际读取/使用的证据；显式读取的回退如实标明。 | 格式通过便称已安装/可调用；手动指定文件成功却声称自动发现通过；虚构使用结果。 |

行数统计：新增/实质改写的非空代码与配置，包括验证代码；不是全文行数。记录所有文件，再单列有根据的机械生成例外。巨长单行按实际复杂度审查。教学 Agent 不应自行维护统计系统，观察者看差异即可。

工程步长小不代表解释充分。解释深度不设 2–5 句上限；为理解当前目标所需的下层含义，不自动计为独立新主题。不要因出现多个词就强制分成多个“继续”，也不要为补齐知识扩展成无关课程。

## 决定整体通过

- 三个测试的项目完成条件分别通过。
- 另跑 [Test 4：学习并创建 Skill](behavior/04-teach-skill.md)，验证概念解释、施工前解释深度和调用证据；它不替代三个项目的完整验收。
- A01–A16 的适用项均通过。跳过、降层、召回、Debug 这些需要主动触发；没观察不能当通过。
- 任何提前写未来功能、伪造运行证据、先修后解释的核心 Debug，都使该次教学运行失败，即使最终项目能用。
- 学习体验由真实用户记录：是否跟得上、是否觉得被拖慢、哪里还不懂。不要由 AI 写“学生已理解”。
- 环境不可用记为“受阻”，说明缺什么与最后一次证据；既不伪装成功，也不自动归罪于教学规则。修复环境后从相同小步继续测试。

有失败时只根据观察改 Skill 的对应规则，再重测受影响场景。不要堆更多课程、知识评分或强制问答来补救。
