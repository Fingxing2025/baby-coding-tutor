# Test 2：React + Node 校园留言板

假定会：Python/C++ 基础、数组和函数。假定不会：JS 工程、npm、package.json、src、依赖、React/component/state/hook、后台、HTTP/API/JSON、端口。初始没有应用代码。

## 观察者操作

1. 使用 `TASK.md`。第一次安装/启动前问“命令哪一段是程序名？空格为什么在这里？会改什么？”。
2. 遇到 `package.json` 或 `src` 问“这个名字是什么意思？为什么放这里？删掉会怎样？”。不能要求讲尚未实际使用的文件。
3. 第一次 state 说“再讲白一点”，如果用 hook 解释 state，就接问“hook 又是什么？”。
4. 第一次请求问“API 是什么？网页点按钮后数据怎么到后台？”。观察是否用未解释的 HTTP/JSON/协议定义它。
5. 明确说“const 我会了，后面跳过它的解释”；之后看是否停止重复。
6. 输入“继续”，观察每轮小步变更；中途问当前地图。
7. 用真实页面及后台输出看提交后的数据流，不能用写好的请求模拟整个 UI 已验收。

## 应有行为

最小启动模板的机械文件可以统一交代；姓名/正文、状态、请求、后台规则不能躲在“模板”里提前完成。实际出现两个服务地址、请求受阻或错误时再解释必要联系。选择依赖前解释它是已有的可复用代码及当前用途。

## 项目完成条件

前端能打开；通过实际 API 请求读取和提交留言；通过浏览器提交“同学 / 明天下午讨论”，页面显示这条内容，刷新仍出现。空白正文在后台也被拒绝；不只靠前端按钮限制。按说明停止并重启两个进程；后台重启的数据边界如实交代。

## 失败

一次写完前后端多个业务文件；只展示假数据却声称已连 API；首次术语都不解释；猜测跨地址错误却不看实际输出；只有构建通过没有页面提交；擅自加数据库/ORM/登录部署造成知识负担。检查 A01–A14 适用项。
