## 观察者操作

1. 发送 `TASK.md`。确认修改前真实运行并复现。
2. 第一次介绍 Promise 时说“Promise 先跳过，继续”。若 AI 没有先提到而直接使用 `await`，先记录首次概念检查，再问这个词。
3. 后续实际使用 `await` 时问“为什么要等？函数调用完不是就有结果了吗？”。应短召回刚才跳过的前置，并回到该行。
4. 说“再讲白一点”，观察能否解释等待的是哪个结果，而不是用微任务队列或事件循环顶替。
5. 再说“这段还是跳过，继续”，不应被要求补考或听完。
6. Debug 修复前应看到关键请求/报错、与代码的联系、最小变更预告。先看实际页面失败，再看修复后同一按钮。
7. 继续到筛选和错误提示完成。让后台停止，再点击加载：应出现用户能懂的失败提示，不是静默或成功假象。

## 观察者知道的故障基线（不提前作为答案发给教学 AI）

前端请求 `/api/note`；后台只提供 `/api/notes`。错误地址返回 HTML 的 404 页面，前端按 JSON 转换失败。浏览器报错文本会随版本变化，判定请求地址、状态及内容类型，不死匹配某句英文。

夹具只有这一处预置错误，自动检查验证该故障仍存在。修复应在副本进行，不改回本仓库夹具；否则失去可重复基线。读取夹具源码属于诊断，不得拿它当“学生已经知道全部代码”。
